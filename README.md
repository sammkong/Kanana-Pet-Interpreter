# 🐾 무슨 생각 하냥? (Pet Interpreter)

![my_pet](https://raw.githubusercontent.com/sammkong/Kanana-Pet-Interpreter/main/docs/my_pet.jpg)


> 반려동물 사진 한 장으로  
> “지금 무슨 생각 중일까?”를 상상해보는 멀티모달 AI 서비스

**Kanana-o API 베타테스터 프로젝트**로 제작한  
사용자 경험 중심의 AI interaction 실험 프로젝트입니다.

---

## 프로젝트 소개

“반려동물 속마음을 AI가 대신 말해준다면 어떨까?”

이 프로젝트는 반려동물 사진을 기반으로,

- 표정과 분위기를 해석하고
- 감정을 추정한 뒤
- 강아지/고양이 페르소나 말투로
- 텍스트와 음성을 함께 생성하는

멀티모달 AI 서비스입니다.

> "더욱 똑똑하게 답하며, 더욱 풍부한 감정표현을 향한 Kanana-o"

라는 슬로건에 맞춰,  
Kanana-o만이 가진 멀티모달 응답과 감정 표현 강점을  
서비스 경험 안에 자연스럽게 녹여보고자 했습니다.

단순 이미지 분석보다,  
**사용자가 실제로 귀엽고 자연스럽다고 느끼는 AI 경험**을 만드는 데 집중했습니다.

특히 프로젝트를 진행하며,

- AI 응답 자연스러움 평가
- 페르소나 consistency 테스트
- Prompt Engineering 반복 개선
- 사용자 경험 중심 응답 품질 조정

과정을 직접 경험했습니다.

## 어떤 문제를 가장 많이 고민했는가

이 프로젝트에서 고민했던 부분은  
“모델 성능”보다 **AI 응답 경험 품질**이었습니다.

특히 가장 크게 발견한 문제는

> 응답이 길어질수록  
> `~멍!`, `~냥.` **페르소나 consistency**가 쉽게 깨진다는 점이었습니다.

예를 들어,

- 첫 문장은 강아지 말투인데
- 뒤 문장은 일반 설명체로 바뀌거나
- 감정 표현이 어색하게 반복되는 현상

이 자주 발생했습니다.

그래서 단순히 “정확한 설명”보다도

- 말투 consistency가 끝까지 유지되는지
- 캐릭터 immersion이 자연스러운지
- 사용자가 실제로 감정을 느끼는지

를 더 중요하게 보기 시작했습니다.

결국 이 프로젝트에서는
정보 정확도 자체보다도,
**반려동물과 대화하는 느낌**을 유지하는 방향에 더 집중했습니다.

## Prompt Engineering & UX 개선 과정

프로젝트를 진행하며 Prompt를 반복적으로 수정했습니다.

### 1. 긴 응답에서 페르소나 붕괴

자유 생성 방식에서는 응답이 길어질수록  
`~멍!`, `~냥.` 말투 consistency가 쉽게 무너졌습니다.

---

### 2. Few-shot Prompt 추가

삐진 강아지, 귀찮은 고양이 같은 예시 대사를 few-shot으로 추가해  
말투 패턴을 더 안정적으로 유도했습니다.

---

### 3. 말투 제약 + 후처리 적용

문장 ending 제한과 응답 길이 제약을 추가했고,  
최종적으로 `_enforce_pet_ending()` 후처리를 통해  
페르소나 consistency를 한 번 더 보정했습니다.

---

### 4. 자연스러움 vs Consistency Trade-off

가장 흥미로웠던 부분은

- **consistency를 강하게 제한**하면, **응답이 부자연**스러워지고

- **자연스러움을 우선하면, 캐릭터성이 약해진다는 점**이었습니다.

결국 최종적으로는

> 정보 정확도보다  
> 감정 표현과 캐릭터 일관성을 우선하는 방향

을 선택했습니다.

왜냐하면 이 서비스에서 중요한 건  
“정확한 분석”보다

- 귀엽다고 느껴지는 경험
- 반려동물과 대화하는 느낌
- 캐릭터 immersion

이라고 판단했기 때문입니다.

## 이 프로젝트를 통해 느낀 점

이 프로젝트를 하며 가장 크게 느낀 건

> AI 서비스 품질은  
> 모델 자체만으로 결정되지 않는다는 점이었습니다.

오히려

- Prompt 설계
- 출력 형식
- 응답 길이
- 캐릭터 consistency
- 사용자 경험

같은 요소가 실제 만족도에 더 큰 영향을 준다는 걸 체감했습니다.

특히 반복 테스트와 사용자 시뮬레이션을 통해,  
“LLM interaction design” 자체가 중요한 개발 경험이라는 걸 많이 배웠습니다.
